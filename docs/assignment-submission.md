## How to evaluate

1. Clone the repository's default branch and follow the README setup instructions.
2. Start the local model and dashboard, select either labelled sample product, and run the pipeline for one prospect.
3. Review generated profile, ICP, research, signals, problem, score, email draft and reply classification.
4. Inspect the model status and inference logs. Switch products and compare their context and outputs.
5. Run the automated suite and source audit.
6. Perform the physical disconnected test described in `local-verification.md` and record the exact tested commit using `git rev-parse HEAD`.

## Evidence provenance and simulation disclosure

The seed companies, contacts, products and conversations are explicitly fictional sample inputs. No model-generated results are seeded into a new installation. The tracked evidence contains actual outputs previously generated by local Qwen3 4B on those fictional inputs. It is historical evidence, not a replacement for running inference in a fresh clone.

Deterministic responses in `tests_local/` are test fixtures only. They test validation, scoping and failure handling without model downloads in CI. They are never used as a production AI fallback.

The `evidence/` directory excludes the personal workspace database, user-created product data, credentials, large model files and the portable runtime. The original assignment PDF is not republished.

## Limits to acceptance

The repository is not presented as having completed the assignment's final physical offline demonstration. That recording remains necessary, and the assignment treats missing offline proof as a failure condition. CPU latency, optional external collection, model uncertainty and the lack of production authentication are documented in the README and technical report.
